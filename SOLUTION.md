# Liquidation signal - описание решения

Задача: построить фильтр токсичных сделок маркет-мейкера на Binance BTC/ETH с использованием данных по ликвидациям с Binance и Bybit. Метрика - `Score(τ)` для τ ∈ {30, 120, 300} секунд, с ограничением на минимальный оборот.

Всё решение собрано в одном ноутбуке: [load_data.ipynb](load_data.ipynb).

## Структура работы

| Раздел | Что делается |
|--------|--------------|
| 1. Загрузка | Чтение parquet, downcast float64 -> float32, дроп лишних колонок (`ticker`). |
| 2. Shape | Сортированность `ts`, дыры, бёрстность, дубликаты, монотонность. |
| 3. Distributions | Распределения цен, объёмов, нотионалов, размеров ликвидаций. |
| 4. Relationships | Главный анализ: drift mid после ликвидаций, maker PnL по alignment. |
| 5. Conventions | Проверка соглашений (что значит `side` в ликвидациях, временные сдвиги Bybit vs Binance). |
| 6. Takeaways | Сводка ключевых выводов. |
| 7. Baseline filter | Реализация фильтра + sensitivity grid + eval на валидации. |
| 8. Submission | Финальная функция `predict(...)` в формате задачи. |

## Ключевые наблюдения из EDA

1. **Данные чистые**, кроме 2048 строк в `ethusdt/trades` с `timestamp=0` (один битый батч, дропается).
2. Покрытие ровно 90 дней (Dec 1, 2025 -> Feb 28, 2026), все 4 источника синхронны.
3. **Bybit liq != Binance liq по структуре**: у Bybit независимый азиатский пик в 0-1 UTC, это даёт дополнительную информацию.
4. **Главный режим - mean reversion** на горизонтах задачи:
   * τ = 1-3 с: слабый momentum (+0.5..+1.5 bps), цена ещё едет за liq.
   * τ = 5-10 с: пересечение нуля.
   * τ = 30-300 с: устойчивая реверсия, цена возвращается и проскакивает в противоположную сторону.
   * Особенно сильно для Bybit: **-7.6 bps** (BTC) и **-14 bps** (ETH) на τ=300s.
5. **Интерпретация**: Bybit-ликвидация - это внешний шок для Binance. Binance делает overshoot из-за спилловера, потом откатывает. Сами Binance-ликвидации уже отражены в BBO в момент `t_liq`, поэтому «горючего» для дальнейшего отката меньше.
6. **Maker PnL по alignment подтверждает гипотезу**:
   * `aligned` (трейд в направлении liq, мейкер ловит реверсию) -> положительный PnL.
   * `anti-aligned` (мейкер ловит overshoot против себя) -> отрицательный PnL.
   * `no recent liq` -> ~+0.5 bps (только ребейт).

## Бэйслайн фильтра

Правило простое:

> **Помечаем сделку как токсичную, если она anti-aligned со свежей крупной ликвидацией в окне 10 секунд.**

То есть `f_i = 1`, если:
* в последние 10 секунд перед сделкой была ликвидация с notional >= 10k-50k,
* и направление сделки противоположно направлению этой ликвидации.

Параметры (`lookback`, `threshold`) подобраны через sensitivity grid на валидации (февраль 2026, BTC, τ=120s).

### Результаты на валидации

* **Положительный Score на всех 3 τ для обоих символов** (BTC, ETH).
* `PnL_filtered` (отброшенные сделки): **-2..-5 bps** - это и есть токсичный поток.
* `PnL_kept` слегка выше `PnL_all` -> Score > 0.
* Доля фильтруемого объёма: **~0.1-1%** от взвешенного - turnover constraint не нарушается.
* Короткий lookback (5-10с) и порог 10k-50k работают лучше: крупные ликвидации редкие, но сигнал от них сильный.

## Что улучшать дальше

1. **Тюнинг параметров под каждый τ** - для τ=300 имеет смысл lookback побольше (30-60с), для τ=30 хватит 5с.
2. **Развести Binance и Bybit в формуле** - у Bybit разворотный сигнал сильнее, его стоит взвешивать выше.
3. **Перейти от hard-rule к ML** - LightGBM на регрессии PnL с фичами:
   * signed liq notional в окнах {1s, 5s, 30s, 2m} отдельно для Binance и Bybit;
   * BBO state (spread, imbalance) в момент сделки;
   * час по UTC как категория для нормализации режима.
4. **Свой кастомный лосс под `Score(τ)`** - если регрессия на PnL не выжимет всё.

## Финальная функция

См. секцию **§8 Submission** в ноутбуке: `predict(trades, bbo, liq_binance, liq_bybit) -> {τ: array}`.
На входе - 4 датафрейма с теми же колонками, что и в публичных файлах (включая `ticker`). На выходе - словарь массивов длины `len(trades)` с бинарными метками фильтра для каждого τ.
